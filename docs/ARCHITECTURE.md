# 代码结构与修改约定

网站使用 Node.js 模板生成静态 HTML，Vite + TypeScript 构建首页的 GSAP / ScrollTrigger 与 Lenis 交互。浏览器只加载本站的 CSS、JavaScript 和图片；GitHub Pages 从 `main` 分支根目录发布。日常内容维护见 [维护指南](MAINTENANCE.md)，本文件适用于修改模板或构建行为。

## 数据到页面的流程

```text
content/*.json + site.config.json
             │
             ▼
src/content.mjs → src/content-validation.mjs
             │
             ▼
src/build-site.mjs
  ├─ src/context.mjs + src/html.mjs + src/urls.mjs
  ├─ src/templates/*.mjs
  └─ 搜索索引、站点地图、404
             │
             ▼
src/output.mjs ← public/ 图片、CSS、JavaScript
             │
             ▼
仓库根目录（发布） + dist/（预览）
```

## 各目录的职责

| 位置 | 职责 |
| --- | --- |
| `content/` | 可编辑内容、首页设置、成员分组、双语界面和机构文案、历史素材映射 |
| `content/templates/` | 新增新闻、成员、研究、论文和个人页的 JSON 草稿模板 |
| `content/schemas/`、`.vscode/settings.json` | 本地 JSON Schema 与编辑器字段提示；跨文件关联和图片存在性仍由内容校验器检查 |
| `site.config.json` | 网站域名、公共邮箱、GitHub 与仓库链接 |
| `src/content.mjs` | 统一读取数据，派生论文搜索文本与链接，并调用内容校验 |
| `src/content-validation.mjs` | 汇总内容格式、双语、图片、路径和关联错误，不写文件 |
| `src/build-site.mjs` | 组织两种语言的页面、搜索索引、站点地图和输出 |
| `src/context.mjs` | 为单种语言的模板提供文案、数据和公共辅助函数 |
| `src/html.mjs` | HTML 转义、纯文本提取等通用处理 |
| `src/image-preview.mjs` | 标记指向图片资源的图片链接，并提供无脚本时的新标签页回退 |
| `src/urls.mjs` | 规范地址、旧地址、语言前缀、旧媒体到本地媒体的转换 |
| `src/templates/` | 按首页、新闻、成员、研究、论文、联系和通用框架拆分模板 |
| `src/output.mjs` | 收集 `public/`，维护生成文件清单并写入发布目录 |
| `src/scaffold.mjs` | 新增命令的参数处理、模板实例化、重复检查和文件更新 |
| `public/` | 样式、浏览器交互和本地素材的源文件 |
| `scripts/` | 构建、预览、校验、新增内容和迁移导入的命令入口 |
| `tests/` | 使用 Node.js 内置测试工具检查关键内容规则和维护流程 |
| `.editorconfig` | UTF-8、换行和缩进约定 |
| `migration/source/` | 原站公开导出，保留追溯依据 |
| `migration/imported/` | 重新运行导入工具得到的比较材料，不参与日常构建 |

`scripts/build.mjs` 保持为简短入口，具体构建逻辑放在 `src/`。新增一种内容的显示方式时，在相应模板中修改；不用把数据、页面和文件操作重新塞回同一个脚本。

## 内容模型

新闻、成员、研究与正文页在同一记录内保存 `en` 和 `zh`，共享 `id`、图片和关联字段。语言字段不再单独分文件，减少新增条目时漏填或关联错误。界面、机构名称和地址的翻译统一在 `ui.json`；分组名称在 `groups.json`。公共网址和邮箱才放在 `site.config.json`。

论文只维护一份正式引文 `html`。`loadContent()` 在内存中派生 `citation` 与 `links`，提供给搜索和校验；不会把派生字段写回内容文件。

页面用 `type` 选择模板，`path` 声明规范地址，`aliases` 声明旧地址。新增成员个人页由数据驱动，不依赖姓名与地址的硬编码表。首页 About 直接渲染首页条目的 `en.html` / `zh.html`；轮播合影自动扫描 `public/assets/home-slides/`；可选图注、图库和展示数量来自 `home.json`。

成员分组采用稳定 `id`，名称和顺序由 `groups.json` 提供。模板按分组顺序输出有成员的分组，组内保持成员数组顺序。

People 页末尾的 Lab Lives 使用独立的 `lab-lives.json`。每张照片保存稳定 `id`、原图、可选显示图、可选活动年份，以及同一记录内的中英文图注和替代文字。相册按年份倒序分组，同年内遵循数组顺序，未知年份单独放在最后；使用紧凑缩略图，点击查看大图。空数组时不输出该区域。它与首页轮播分别配置，共享原有图片资源和站内预览功能；新增相册照片不会改变首页。

## 双语与地址约定

英文页面使用 `/`、`/news/` 等规范地址；中文使用 `/zh/` 前缀。两种版本是完整、独立的 HTML，不依赖运行时把整页文字替换为另一种语言。

模板通过当前语言上下文读取文字和生成地址。正文中的站内链接也经过统一转换，媒体路径保持 `/assets/`。全站搜索读取对应语言的索引，页头切换指向相同页面的另一语言版本；浏览器脚本保留定位锚点。

旧地址仍生成默认英文版本，并指向同一规范地址。修改地址处理逻辑时必须同时保留：

- 原站页面地址及 WordPress 页面 ID 链接的转换。
- 中英文内部导航与搜索结果的语言一致性。
- `canonical`、`hreflang`、分享元数据和站点地图之间的一致性。
- 已发布内容 `id` 的稳定性，避免新闻与研究定位链接失效。

既有栏目地址也是站点界面约定的一部分。新增普通正文页不需要更改模板；调整顶栏栏目或现有栏目地址时，应同时检查模板中的导航、栏目入口与搜索链接。

## 输出与浏览器代码

异步构建先加载和校验内容，再由 `src/browser-assets.mjs` 调用 Vite 在内存中打包首页增强脚本，然后准备页面并交给输出模块。内容校验或打包失败时不写入发布文件。生成文件同时写到根目录和 `dist/`，由 `generated-files.json` 记录范围；清理时只处理清单中的旧生成文件，不把源目录当作发布输出删除。

`public/styles.css` 负责排版，`public/site.js` 负责移动菜单、语言切换锚点、搜索、筛选、首页轮播和图片预览。界面提示文案来自 `ui.json`，由页面提供给脚本，避免中英文文案在脚本内重复维护。CSS 和 JavaScript 的内容会生成资源版本号，帮助浏览器加载更新。

图片预览使用原生 `<dialog>`，无需外部插件或 CDN。构建时只标记正文中「包含图片且链接到图片资源」的链接，成员及项目卡片继续跳转详情页。首页轮播照片组成一个图库，About 插图单独分组，新闻和研究图片按各自条目分组。预览支持方向键、关闭按钮、Esc、背景点击和触屏滑动；关闭后恢复滚动与焦点。查看原图及无 JavaScript 的回退均在新标签页打开，不离开当前页面。

首页轮播由 `src/home-slides.mjs` 扫描 `public/assets/home-slides/`，自然排序后通过 Sharp 读取尺寸与 EXIF 显示方向。`loadContent()` 为异步函数，将扫描结果派生为内存中的 `home.hero`；源码 JSON 不再维护图片清单。`home.json` 的可选 `heroLabels` 仅覆盖图注，新图片无需配置即可进入中英文首页。第一张用作分享预览。图片保持完整比例与固定展示高度，自动切换不触发屏幕阅读器播报；手动切换会播报图片位置。轮播保留键盘、触屏、暂停按钮及减少动态效果支持，未激活的照片不进入键盘焦点顺序。

`npm run dev` 监听源文件变化，自动重新构建并通知预览页面刷新。内容校验失败时保留上一次正常输出，修复后继续更新。自动刷新只用于本地预览，不是线上网站功能。

模板调整应保留键盘可操作性、跳转正文、图片替代文字和无 JavaScript 的基本导航。新闻多图保持等高展示、完整比例，小屏幕按空间换行；图片预览与原图链接保持正确关联。

## 排版与视觉验收

学校品牌的颜色、推荐字体优先级、校徽留白与华表云纹来源见 [品牌规范](BRAND.md)。所有页面共享同一组样式变量与页头页脚，不在单页中另设主题色。

首页采用学术网站的信息组织方式：介绍与合影并列，其后优先展示新闻与论文（桌面端双栏），再展示研究项目，最后为 About。减少重复栏目标签与口号，优先使用清楚的栏目名称。内容密度通过网格、间距和图片尺寸调整，不靠缩小正文或截断标题。

- 首页按视口组织为五个章节，使用最小屏幕高度；长内容自然延伸，避免截断或嵌套滚动。内页继续使用紧凑阅读布局。首页滚动细节见 [滚动交互说明](SCROLLING.md)。
- 所有内页的面包屑、标题区和内容区与页眉共用 `.wrap` 容器及 `--width` 最大宽度。新闻标题和正文使用完整内容宽度；单图在内容区内居中，最大宽度 720px、最大高度 480px，保持原比例且不超出手机屏幕，可点击查看大图。多图继续等高并排。不另设居中的窄页面容器，以免左右边界错位。
- 首页研究项目在宽屏一行四项，平板两列，手机以小图和完整标题横向排列；增加项目后自然换行。
- 成员目录使用照片与姓名并列的卡片，按分组展示。桌面列宽按实际图文计算并分散对齐，首列贴齐内容左边界、末列贴齐右边界，避免固定等分列的尾部大块空白；同组内各行共用列轨道，末行从左侧开始。窄屏为两列或单列，个人页入口始终清晰可见。
- 新闻和研究配图使用 `object-fit: contain`，完整保留图中信息；多图在空间允许时等高并排。成员肖像可用 `cover`。
- 使用真实的中英文长标题检查 320px、390px、768px、901px 和宽屏；不得出现整页横向滚动、文字裁切或按钮重叠。
- 检查导航、语言切换、搜索、筛选和键盘焦点。搜索关闭后焦点应返回原按钮，减少动画的系统设置应继续生效。

## 编写和验证约定

- 使用 ESM（`import` / `export`）和 Node.js 内置模块，新增依赖前先确认是否必要。
- 使用两个空格缩进和清晰的函数名；较长模板拆成有含义的片段，避免单行堆叠整页逻辑。
- 内容留在 JSON，布局留在模板，通用 HTML 和地址处理留在对应辅助模块。
- 普通文字插入 HTML 时转义；允许富文本的字段经过统一 HTML 处理和地址转换。
- 校验函数返回错误信息；命令入口负责打印错误和设置退出状态。
- 测试针对地址冲突、双语缺失、成员关联、错误日期和新增命令写入等实际故障，不依赖当前内容数量。

```sh
npm run test
npm run verify
```

`verify` 依次执行 TypeScript 检查、测试、构建和生成页面检查。测试也覆盖通过命令新增内容、填写后构建两种语言、个人页关联和旧地址保留的维护流程。`scripts/check.mjs` 进一步核对内容是否完整显示、图片及链接是否存在、两种语言搜索是否正确、元数据和站点地图是否一致。

修改视觉模板后，还应在浏览器查看英文、中文、宽屏与窄屏。自动检查通过不能替代对排版和交互的确认。

GitHub 工作流运行同样的验证，并检查重建后是否产生未提交差异。因此提交时需要包含最新的根目录生成文件，具体发布步骤见 [维护指南](MAINTENANCE.md#10-发布到-github-pages)。
